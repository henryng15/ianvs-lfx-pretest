## 1. The fix does not extend to modules that the loaded file imports

@Aryansingh-ai listed this as a compatibility consideration and noted it was not
demonstrated. It is demonstrable. Fixture mirrors the repository's real shape: two
Examples, each with its own `basemodel.py` (41 such files exist) importing its own
sibling `utils.py` (10 such files exist).

```text
--- main @ 37a9c60 ---
  load  resolved sys.modules key                      its code    its utils   predict(1)  #keys
  A     basemodel                                     example_A   example_A   1           1
  B     basemodel                                     example_A   example_A   1           1

--- pr-558 @ b99161f ---
  load  resolved sys.modules key                      its code    its utils   predict(1)  #keys
  A     basemodel_f3f64bab699cb16b508b9c58d085eba3    example_A   example_A   1           1
  B     basemodel_0b091c108d51ae40d4e1078665699b86    example_B   example_A   1           2

  sys.modules keys for utils: utils        <-- one key, two different files
```

`example_B`'s own `basemodel` now loads correctly — the PR working as intended. But it
still binds `example_A`'s `utils`, so `predict(1)` returns `1` where the Example's own
helper returns `100`. The hashed identity applies only to the file `load_module()` opens;
anything that file imports still resolves by bare name through the `sys.path` entry the
function inserts just above.

Why this is worth closing before merge: on `main`, `example_B` never executes at all,
which is visibly broken. Under this PR it executes and returns a plausible wrong number.
For a benchmarking framework that is the harder failure to notice, and it becomes harder
still once the obvious collision is gone.

Reproduce: `python3 tools/probe_pr558_transitive.py ianvs` —
https://github.com/henryng15/ianvs-lfx-pretest

## 2. The hashed `__name__` removes pickle recoverability (latent)

Stating the boundary first: **no shipped Example is broken by this today.** I checked.
The issue is that the PR removes a property without recording that it did.

`sedna/core/lifelong_learning/lifelong_learning.py` and
`knowledge_management/*.py` persist the knowledge base through
`FileOps.dump` → `joblib.dump`. pickle does not serialise a class; it stores
`obj.__class__.__module__` as a string and re-imports that name on load. This PR changes
that string from the bare basename to `<basename>_<md5 of the absolute path>`.

Same fixture, both refs, unpickled in a fresh interpreter:

```text
--- main @ 37a9c60 ---
  CLASS_MODULE                      taskdef
  UNPICKLE (source dir on sys.path) LOAD-OK TaskDefinitionByDomain('Cityscapes')

--- pr-558 @ b99161f ---
  CLASS_MODULE                      taskdef_401cfc800cc0a1806b5a8207c97ee637
  UNPICKLE (source dir on sys.path) LOAD-FAIL ModuleNotFoundError: No module named
                                    'taskdef_401cfc800cc0a1806b5a8207c97ee637'
```

On `main` the artifact is recoverable by exactly the `sys.path` insertion this function
already performs. After this PR the recorded name matches no file on disk under any name.
The md5 covers the *absolute* path, so it also differs per checkout directory — across
two runs from different temp directories the suffix was `c11480c6…` then `401cfc80…` for
the identical source file.

**Why it does not fire today, verified:** `task_index` is
`{"extractor": self.extractor, "task_groups": self.task_groups}`; `Task` and `Model` are
Sedna classes; `t.model` is replaced by a path string before the dump; and every shipped
`task_definition` module returns the extractor as a plain `dict`
(`robot-cityscapes-synthia/.../task_definition_by_domain.py:58`,
`robot/.../task_definition_by_origin.py:65`,
`cityscapes-synthia/.../task_definition_by_origin.py:81`, and the `bdd` variant). So the
pickle currently holds no Example-defined class.

But `task_definition`, `task_relationship_discovery` and `unseen_task_detect` exist
specifically so an Example can supply its own class, and their return values flow
straight into that pickle. Nothing states they must not. Today such an artifact is
recoverable; after this PR it is permanently unloadable, with no diagnostic beyond a
`ModuleNotFoundError` naming a module that never existed.

One option that keeps everything this PR gains: key `sys.modules` uniquely as you do, but
leave `mod.__name__` at the bare basename. If you prefer the hashed `__name__`, then
writing the invariant into the docstring would be enough.

Reproduce: `python3 tools/probe_pr558_pickle.py ianvs`
