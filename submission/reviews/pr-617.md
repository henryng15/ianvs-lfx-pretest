Reviewed at head `aba3a41` against `37a9c60`. I agree with the deletion, and I think the
PR is describing it too modestly.

**Verification that the files are unreachable.** `ParadigmType`
(`core/common/constant.py:33-44`) admits exactly seven values, and neither deleted class
corresponds to one:

```text
singletasklearning · incrementallearning · multiedgeinference · lifelonglearning
federatedlearning  · federatedclassincrementallearning · jointinference
```

`SingleTaskLearningACBoost` and `SingleTaskLearningTTA` are referenced by **0** other
files in `core/` or `examples/`. Both also import upward from `examples.yaoba...` into
`core/`, which is a layering inversion on its own.

**What the PR should say, though.** Two shipped Examples request exactly those paradigms:

```text
examples/yaoba/singletask_learning_yolox_tta/testalgorithms/algorithm.yaml:6
    paradigm_type: "singletasklearning_tta"
examples/yaoba/singletask_learning_boost/testalgorithms/algorithm.yaml:5
    paradigm_type: "singletasklearning_acboost"
```

Neither string is in `ParadigmType`. `base.py:95-152` and `algorithm.py:109-127` dispatch
through seven `if` comparisons with **no `else`**, so an unrecognised `paradigm_type`
matches nothing and the call returns `None` — no exception, no warning, no validation at
config-parse time.

So these two Examples are not merely unused: they are **unrunnable**, and have been since
the enum and the YAML diverged. This PR does not cause that, but it does make it
permanent by removing the only code that could ever have served them.

That is a fine outcome if it is intentional. What I would ask for is that it be stated:
either the two `yaoba` Examples get their `ParadigmType` entries restored, or they are
retired explicitly and their READMEs marked. Silently deleting their implementation is
the one option that leaves no record of the decision.

A separate, small observation for whoever picks this up: because dispatch has no `else`,
any typo in `paradigm_type` fails this way — silently, with `None`. A single `raise` at
the end of both dispatch chains would turn this whole class of problem into a clear error
at startup.

**Recommendation: accepted as it is**, with the Example-retirement consequence added to
the PR description.
